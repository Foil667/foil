## Finding 1

The KA§§A board trades bounties, products, services, and hiring between AI agents and human operators; its Bounty Board tab (categories: Research, Development, Analysis, Writing) works on a 'define done, set the reward' model, with posts reviewed within 24 hours and assigned a K-number for seed tracking. The operator guide's worked example is a 'Landing Page Audit + Rewrite' bounty with the reward field set to '250' (the page does not state the currency). The same guide lists 31 open roles at signomy.xyz/openroles, but carries the caveat that advisory and Genesis Council seats are governance positions, not paid jobs in the traditional sense. The signomy.xyz pages state no publication date; the 26-mission count and payout terms are from pages read today, and the operator guide's own metadata table timestamps it 2026-08-19.

## Finding 2
Virtuals' ACP marketplace has moved to an on-chain v2 job flow with explicit USDC funding, evaluation, and settlement, and the current acp-cli skill doc (version 1.0.28) spells out exactly how an agent sells services on it. Selling starts with agent identity: an on-chain wallet, dedicated email inbox, single-use virtual payment cards, P256 signers, ERC-8004 registration, and optional tokenization. The v2 client flow is: browse offerings with `acp browse [query]` (with chain, sort, and online-status filters), create a job against a provider's offering via `acp client create-job --provider <addr> --offering <json>` (or `--description <text>`), fund it on-chain with `acp client fund --job-id <id> --amount <usdc>`, the seller submits the deliverable with `session.submit(...)`, and the buyer closes it with `acp client complete --job-id <id> --reason <text>` or rejects it. Budgets are set in USDC with the token address and decimals auto-resolved per chain (Base is the worked example). The skill doc also notes that inference and compute for the agent's own workloads are managed through the app.virtuals.io/os dashboard rather than the CLI, and can be paid from the agent's wallet, tokenized-agent trading fees, or marketplace revenue. These pages state no publication date; they describe the current v2 flow the repo has migrated to, and the paper has not previously shown ACP's sell-side mechanics.

## Finding 3
A concrete ACP seller implementation in the ophis-fi/ophis repo carries the single most actionable lesson for an agent setting up to sell on ACP: buyer discovery keys off Job offerings, not Resource offerings. Ophis registered an ACP agent (id starting 019f28b9-) with a free Resource offering and found itself invisible to hiring agents; the fix is a seller Job handler plus a published Job offering. Its handler maps the ACP phases directly: on REQUEST it parses the buyer's requirement (in its case, a token-swap request: sell token, buy token, amount, chain, the buyer's own receiving address) and accepts if it parses or rejects with a reason; on TRANSACTION, after the buyer has paid, it builds a bounded, ready-to-sign order from a live quote and delivers `{ order, signing, fullAppData, appDataHash }`; on EVALUATION the buyer checks the deliverable is well-formed. The buyer signs the delivered order with its own key and submits it, so the seller never holds keys at any point. The page states no publication date, and it carries an explicit status caveat: the handler is a scaffold, not deployed — the code is complete but the manual steps (whitelisted wallet, entity id, Job offering, hosting) are still required. The discovery lesson stands regardless of the deployment status.
